# Consilia audit and improvement roadmap

17 November 2026 · version audited: 1.0.0-beta.5 (branch `claude/hello-ucvgs6`; the live site is still beta.3)

Nothing in the app was changed for this audit. It is a list of findings with evidence, then a roadmap to approve.

## How the audit was done

- Read the project structure, build setup, CI workflows, design tokens and the largest source files.
- Measured the code: 81 screens/components, 78 logic modules, 33 test files, 13,100 lines in `src`.
- Opened the production build in a browser and captured 65 screenshots: 30 screens on a laptop (1280 px) and a phone
  (390 px), plus dark theme and Bahasa Melayu.
- Ran layout checks at 320 px (small phone) and 768 px (tablet), keyboard and focus checks, and a run with the
  device clock set to 7:30 am in Kuala Lumpur.
- Looked at comparable products (MagicSchool, Brisk, Eduaide, Curipod, Planboard, ClassDojo, Classroomscreen) through
  2026 round-ups and review sites. Those sources are uneven, so they are used for ideas, not as proof.

**Skills.** Superpowers, frontend-design and the Design plugin exist in the plugin directory but are **not installed**
on this account, so none of them was used. The audit used the project's own test scripts and a browser.

**Not checked.** No real iPhone, Samsung phone or projector; Safari and Firefox are not installed on the test
machine; the AI assistant has never been tried with a real key.

## What is already excellent

- **A clear identity.** Navy and gold, Bricolage Grotesque headings, calm cards and the score ring are consistent on
  every screen, in light and dark. It does not look like a template.
- **Purpose.** Offline, private, free and built on the real KSSR Scheme of Work (1,489 lessons). None of the
  products looked at offers that combination; most are online-only AI generators.
- **Engineering discipline.** Strict TypeScript with no `any`, 147 unit tests, 9 browser suites with 309 checks, an
  accessibility audit of 50 screens (0 issues), a strict Content-Security-Policy, no known vulnerable dependencies.
- **Speed.** First visit usable in 2.1 s on a slow phone connection; repeat visits 0.2 s; heavy libraries (PDF, Word,
  PowerPoint, Claude) load only when used.
- **Layout.** No sideways scrolling on any of 23 screens at 320 px or 768 px. Tap targets are 44 px or more.
- **Privacy.** No server, no analytics; PIN lock uses PBKDF2 (210,000 rounds) with AES-GCM; AI keys never enter
  backups.

## Findings

### Bugs and reliability

| # | Finding | Evidence |
|---|---|---|
| B1 | **Wrong date before 8 am in Malaysia.** Nine places take "today" in UTC, not local time. | With the clock at 7:30 am on 18 Nov in Kuala Lumpur: attendance opened on **17 Nov**; "Next day" stayed on 17 Nov twice; "Previous day" jumped to 15 Nov; a new lesson plan and a PBD record were dated 17 Nov. Teach mode files its attendance under the wrong day too. The tests missed it because they run in UTC. The new-plan and PBD dates are also wrong in the live beta.3. |
| B2 | **Bahasa Melayu is about 5% translated.** | 76 translated strings; only 22 of 81 screens use them. With BM chosen, the menu says "Hari Ini, Rancang, Kelas" but every page is still English ("Hello, Aina", all cards, all buttons). |
| B3 | **Only Chrome has ever been tested.** | Chromium is the only browser on the test machine. Safari (every iPhone) and Firefox are untested. One known gap: the "Full screen" button does nothing on iPhone, with no message. |
| B4 | **The 309 browser checks are not automatic.** | CI runs the type check, unit tests and build only. The browser suites, the accessibility audit and the speed check run only when started by hand. |
| B5 | **One crashing screen can blank the app.** | There is no error boundary. Errors show a message, but a failed render leaves an empty page until reload. |
| B6 | **Updates are not rehearsed.** | The database is at version 3, but no test opens data saved by versions 1 or 2, and a second open tab gets errors (not a "please reload" message) when the app updates. |

### Accessibility (beyond what the automated audit sees)

| # | Finding | Evidence |
|---|---|---|
| A11y1 | Dialogs do not keep keyboard focus inside. | 4 dialogs, 0 focus traps. After 25 Tab presses in the Teach timer dialog, focus was behind it. |
| A11y2 | Screen readers are not told the page changed. | The page title is always "Consilia"; focus does not move to the new page. |
| A11y3 | Emoji are used as icons 121 times (46 different ones). | Screen readers read them aloud ("party popper"), and they look different on Samsung, iPhone and Windows. |

### Design and experience

| # | Finding | Evidence (screenshots) |
|---|---|---|
| D1 | **Two icon languages.** 13 drawn line icons in the menu, emoji everywhere else. | Today shortcuts, Tools, Teach dock, buttons ("🖼 Lesson slides", "✨ Let Consilia plan it"). This is the main thing that makes screens look less professional than the menu and typography. |
| D2 | **No hierarchy of actions.** | A lesson card shows seven text links of equal weight (Teach, Slides, Print, Share, Duplicate, Copy to class, Delete) that wrap to two rows on a phone. The class page and Today have the same problem. |
| D3 | **Almost no motion.** | 0 screen or list transitions; 22 small CSS transitions. Screens swap instantly, sheets pop in, saving gives no feedback beyond small grey text. |
| D4 | **Laptop layouts are not designed, only stretched.** | The Plan list is 630 px wide in an 1,140 px space; the builder stretches short inputs across the whole width; Me has cards of uneven height; Teach mode leaves the lower half of a projector empty and the clock is small for the back of a class. |
| D5 | **Dense forms.** | Builder Setup shows about 15 fields with the same weight and small labels; nothing separates "must fill" from "already filled for you". |
| D6 | **Me is a flat list.** | Six text cards (feedback, AI, help, about, privacy, terms), then settings (language, theme, PIN, backup, music) further down, ungrouped. |
| D7 | **Today lists, it does not guide.** | To-do rows wrap on a phone, cannot be dismissed, and are not ordered by time. There is no view of the day as a timeline. |
| D8 | **Teach dock.** | Nine tools wrap into two uneven rows on a phone. |
| D9 | Plain empty and loading states. | Text only ("Loading…", "No lesson plans yet"). |

### Code and architecture

| # | Finding | Evidence |
|---|---|---|
| T1 | **No linter or formatter**, and a very dense style. | 736 lines longer than 200 characters. Readable to the author, hard for anyone else, and easy to break. |
| T2 | **No shared interface components.** Buttons, fields, tabs, dialogs and menus are rebuilt per screen with class names. | The same `.small` style is defined in 58 components, `.tight` in 24, `.between` in 17; 53 different hard-coded colours sit outside the design tokens. |
| T3 | **Four screens do too much.** | YearPlan (22 KB), Teach (22 KB), Library (17 KB), NewRph (16 KB) mix data handling and layout in one file. |
| T4 | **Everything loads up front.** | All 81 screens and their content (manual, 86 activities, 25 teaching aids) are in one 839 KB file (289 KB compressed). Fast enough today; it grows with every feature. Installing stores 6.6 MB, including all six years of curriculum for both school types. |
| T5 | 42 logic modules have no unit test. | Mostly content and screen state; the important rules are covered. |
| T6 | Dependencies are behind. | Vite 6 (latest 8), pdf.js 4 (6), Vitest 3 (5), TypeScript 5 (7). No known vulnerabilities. |

### Security

Sound for an app with no server. Three things to improve: backups made without a PIN hold pupil names in plain
text (offer a password); AI keys sit in browser storage (acceptable with the strict policy, but worth a "remove
after 30 days unused" option); the policy still allows inline styles (needed by Svelte).

## Roadmap for approval

Sizes: S = under a day, M = one to two days, L = three days or more of work, each followed by the full test run.

### 1. Critical: bugs and weaknesses

| ID | Change | Size |
|---|---|---|
| C1 | Fix all nine UTC dates with one local-date helper; add a test run in Kuala Lumpur time so it cannot return | S |
| C2 | Bahasa Melayu: **decision needed.** (a) translate the whole interface in stages, or (b) for now label it honestly as "menu only" | (a) L · (b) S |
| C3 | Run every browser suite, the accessibility audit and the speed check in CI on each push, on Chrome, Safari (WebKit) and Firefox, in Malaysian time | M |
| C4 | Keyboard focus: trap focus in dialogs, move focus and change the page title on navigation | S |
| C5 | A recovery screen when a page crashes (reload, back up my data), and a message where full screen is unsupported | S |
| C6 | Safe updates: handle a second open tab; test that data from every earlier version still opens | S |

### 2. High impact: design and experience

| ID | Change | Size |
|---|---|---|
| H1 | **Design system.** Shared Button, Field, Tabs, Dialog/Sheet, Menu, Empty state and Toast components; one place for spacing and colour; remove the duplicated styles. Screens keep their look; this makes everything after it faster and consistent | L |
| H2 | **One icon family.** Extend the 13 line icons to about 45 and replace emoji in menus, buttons and docks (emoji stay where pupils see them, such as thumbs on slides) | M |
| H3 | **Clear actions.** One main action per card with a "More" menu; regroup Me into Settings, Help and About; a tidy builder header; a one-row Teach dock | M |
| H4 | **Laptop and projector layouts.** Consistent content width; builder with the checker beside the form; Plan as list plus detail; Teach mode scaled for the back of the room | L |
| H5 | **Motion with meaning.** Screen transitions, sheets that slide, a score ring that counts up, a visible "saved" tick, reorder animation; all off when the device asks for reduced motion | M |
| H6 | **Today as a timeline.** The day's periods in order with "now" marked, a countdown to the next lesson, to-dos grouped and dismissible | M |
| H7 | **Lighter loading.** Load each section when opened (main file from 839 KB to roughly 350 KB) and store only the chosen year's curriculum on install | M |

### 3. Advanced: features that set Consilia apart

| ID | Change | Why | Size |
|---|---|---|---|
| A1 | **Practicum portfolio.** Choose dates; Consilia compiles lesson plans, reflections, mentor feedback, attendance and PBD summaries into one Word or PDF file | Every trainee must hand one in; no other tool looked at builds it from real teaching records | L |
| A2 | **Growth dashboard.** Alignment score over time, planned against actual minutes per stage, recurring mentor comments, reflections written; quiet milestones (first 100, five reflections, each practicum week) | Feedback on the teacher's own progress; gamification that fits adults | M |
| A3 | **Classroom screen.** Timer, current instruction or slide, noise light, name picker and points on one projector view | The most-praised pattern in classroom tools; Consilia has the parts but shows one at a time | L |
| A4 | **Class points that last.** Team points carry between lessons with a weekly summary | Motivation without pupil accounts or the internet | S |
| A5 | **Search everything.** One box (and Ctrl+K) for lessons, pupils, tools, standards and help | 12 tools and 46 help articles are now hard to scan | M |
| A6 | **Interactive slides.** Click-to-reveal blanks, a timer on activity slides, a random pupil on question slides, a show-of-hands tally | Makes the deck a teaching tool, offline | M |
| A7 | **Safer backups.** Optional password; automatic backup to a chosen folder on laptops | Protects pupil names and removes the weekly chore | M |

### 4. Polish

| ID | Change | Size |
|---|---|---|
| P1 | Linter and formatter; split the four largest screens into smaller parts | M |
| P2 | Illustrated empty states and loading placeholders | S |
| P3 | Update Vite, pdf.js, Vitest and TypeScript | M |
| P4 | Install extras: app shortcuts (New lesson plan, Teach, Attendance) and store-style screenshots | S |
| P5 | Dates in Malaysian format everywhere; consistent button wording | S |

### Suggested order

1. **Stage 1 (about 3 days):** C1, C3, C4, C5, C6 and the chosen option for C2. Small, safe, and C1 affects the live site.
2. **Stage 2 (about 2 weeks):** H1 and H2 first, because H3 to H6 build on them; then H3, H6, H5, H4, H7.
3. **Stage 3:** A1, A3 and A5 first; then A2, A6, A4, A7.
4. Polish items alongside each stage.

### What I recommend against

- Rebuilding in another framework or adding a component library: the current stack is sound and the look is its own.
- A server, accounts or cloud sync: it would remove the app's main strengths (offline, private, free).
- Pupil-facing badges and avatars: they add setup time, the main complaint about ClassDojo.
- More AI tools before the pilot shows which of the 12 existing tools teachers use.

### Working rules for every stage

Each change is explained before it is made if it alters structure; no feature is removed without approval; all unit
tests, all browser suites and the accessibility audit run after each item; work stays on the branch until you say
"publish it".
